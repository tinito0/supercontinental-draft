## HIGH (Hard Gate)

**F-01 · R-25 · Plain `accent` used as text color fails AA.** `text-accent` (not `-soft`/`-hover`/`-deep`) appears
33 times [count]. `accent` #3a66c4 on surface is 3.42:1 and on canvas 3.63:1 [measured]: fails 4.5:1 for normal text,
passes only for large text and non-text. The doc itself says blue text on dark is `accent-soft`, so code and doc
disagree. Needs a per-site check of size. Fix: use `text-accent-soft` for text, keep `accent` for fills and borders.

**F-02 · R-25 / non-text contrast · Control boundaries at 10–20% alpha.** The doc sets hairlines `border-line/10…14`
and controls `/16–20`. WCAG 1.4.11 asks 3:1 for the boundary of an input or button against its background. [unverified]
I did not read `--c-line`, so this is not measured yet. Probable fail on `.input`/`.select` borders. Fix: measure
first with `contrast-check.py`; give fields a boundary or fill that reaches 3:1, keep hairlines for decoration-only dividers.

## MEDIUM (Purpose-Gate)

**F-03 · R-01, R-13 · A second accent (cyan) with a glow, contradicting the doc.** `.app-guide-ring` and
`.app-guide-popover` (`index.css:909-930`) use `rgba(34,211,238,…)` border plus `0 0 30px` glow. The doc says one
accent, no cyan, no glows as decoration. The sibling `.scout-guide-*` (`index.css:851-874`) does the same job in crest
blue with its own 28px glow. Two near-duplicate guide systems. Fix: merge into one guide component on crest blue, no glow.

**F-04 · R-01 · Decorative gradient panel.** `components/league/club/ClubStory.jsx:39`:
`bg-gradient-to-r from-accent/15 to-transparent`. The doc bans gradients as decoration. Fix: flat `bg-accent-deep`
or a plain panel; the reason to emphasise the closing chapter must come from type and spacing (principle 1).
Note: `broadcast.css` gradients (OBS frame) are an undocumented exception; the doc should name it. `Pitch.jsx:225`
stripes are functional grass, fine.

**F-05 · R-10 · Blur has no dose cap.** `backdrop-filter: blur(14px)` on both guide popovers, `blur(2px)` on
`.sidebar-backdrop`, and `backdrop-blur` in 13 files [count]. The doc has no glass policy. Fix: write one (blur only
on the single floating layer, never on the shell) and remove the rest.

**F-06 · R-12 · Off-token shadows.** Guide popovers use `0 20px 70px` (token `shadow-lg` is 16px/40px).
`shadow-[0_0…]` or `drop-shadow` appears 5 times [count]. Fix: only `shadow-sm/md/lg`.

**F-07 · R-06 · Text below the doc's own minimum.** `text-[10px]`/`text-[11px]` in 58 files and `text-[9px]` in 7
[count]. The doc says labels are 11–12px. 9px and 10px are not readable on a phone at 360px. Fix: floor at 11px
(12px for anything the user must read, not just scan), add the floor to the doc.

**F-08 · R-06 · Uppercase and tracking spread.** `uppercase` in 53 files, `tracking-wider` in 20, `tracking-widest`
in 3 [count]. `.eyebrow` is 11px, 600, `tracking 0.14em`, uppercase: the exact "wide-tracked uppercase label" tell,
allowed only with a written reason. The doc gives one (eyebrows, section titles, table heads), but usage exceeds that
scope. Fix: audit the 53 files against the doc's three allowed uses; ban `tracking-widest`.

**F-09 · R-11 · Pills.** `rounded-full` in 58 files [count]. Dots, avatars and crest masks are legitimate; the doc
bans "pills for metadata". Fix: review only chips and badges; list which are state markers (R-09).

**F-10 · R-19 · Endless pulse outside the allowed list.** `components/Pitch.jsx:154` uses `animate-pulse` on a
marker holding a player. The doc allows loops only for a live indicator, skeletons, spinners. The five live dots
(FeaturedMatch, FixtureRow, MatchParts, LeagueHomeScreen, LeagueMatchesScreen) mark a real live state and have no
glow: those are fine. `PlayerModal.jsx:847` and `TransferFeed.jsx:50` use Tailwind `animate-pulse` for skeletons
instead of the app's `.skeleton` (`skeleton-pulse 1.4s`), so they may not honour the reduced version [unverified].
Fix: Pitch marker gets a one-shot highlight or a static ring; skeletons use `.skeleton`.

**F-11 · Doc vs code · Weight 900.** `index.css:885` and `:942` (`.scout-guide-skip`, `.app-guide-close`) use
`font-weight: 900`, plus `broadcast.css` and `broadcastBracket.css`. The doc allows 400/500/600/700 only. Fix: 700.
If the broadcast files keep 900 on purpose, document it as the OBS exception.

**F-12 · R-29, R-31 · Hardcoded color literals.** 82 lines in `index.css` carry hex or `rgba()` outside `:root`,
e.g. `#9ca3af`, `rgba(12,16,23,.96)`, `rgba(58,102,196,.95)` in the guide blocks. The doc says tokens only.
`bg-[#…]` appears in 2 files [count]. Fix: `rgb(var(--c-…) / α)`.

**F-13 · transitions-polish · `transition: all`.** `index.css:636` (`transition: all 0.2s ease`) breaks the doc's
"no `transition-all`" and uses a hardcoded duration and the generic `ease` keyword. Fix: list the properties and use
`var(--dur-base) var(--ease-out)`.

**F-14 · transitions-polish · Raw Tailwind durations bypass the tokens.** `duration-150` ×10, `duration-300` ×4,
`duration-200` ×3, `duration-500` ×1 [count]; `.btn` itself uses `duration-150` (`index.css:248`). Tokens are
120/180/220. Fix: map each to `fast`/`base`/`move` by usage, not nearest number. The 300ms and 500ms sites need a look
first (they may be the meters, which the doc allows at 300ms).

**F-15 · transitions-polish · Guide rings animate layout properties.** `index.css:860` and `:916` transition
`left`, `top`, `width`, `height`. The doc's exceptions list only pitch markers and meters. Fix: position with
`translate` and size with `scale`, or add the exception to the doc with the reason (single small fixed element).

## Decision for you, not a finding

**D-01 · transitions.dev vs the doc's Motion section.** The library installs 43 transitions plus a token scale
(40/80/150/250/350/400/500ms, bounce easings, stagger, count-up digits). The doc forbids stagger, bounce and
count-up, and runs a faster scale (120/180/220). Adopting the library wholesale would contradict the doc. Options:
(a) keep the app's scale and use transitions-polish only to flag off-scale values (recommended: it already matches
the open/close asymmetry rule); (b) adopt the library scale and rewrite the Motion section; (c) allow-list a few
transitions (toast, accordion, sliding tabs) and keep the bans for the rest.
