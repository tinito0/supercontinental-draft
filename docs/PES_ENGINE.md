# PES 2021 database & kit engine

Engine and workspace for editing the eFootball PES 2021 (PC) database, save file and kits inside Supercontinental
Draft. This document records what is verified, how the pieces fit, how to operate it, and what is still open.

## 1. Supported input (explicit)

| Input | Format | Editable | Verification |
|---|---|---|---|
| `common/etc/pesdb/Team.bin` | WESYS container, zlib; 704 × 1532-byte records | 63 of 65 exposed fields (id and nonPlayableLeague read-only) | 64 fields equal to the EJOGC CSV export for 704/704 teams; nonPlayableLeague 598/704 |
| `…/Player.bin` | WESYS; 27 437 × 312-byte records | 48 of 57 exposed fields (id + 8 unverified read-only) | See §3 |
| `…/PlayerAssignment.bin` | WESYS; 19 404 × 16-byte records | `playerId`, `teamId`, `shirtNumber`; add/remove rows | References checked against Player/Team.bin; shirt number = byte + 1 (real squads) |
| `…/Coach.bin` | WESYS; 1 851 × 100-byte records, no header | `name` (44 bytes), `country`, `adaptability` | `pes/formats/pes2021/coachLayout.js`: EJOGC Coach table; 5/5 EJOGC team exports and 706/706 EDIT coaches equal; Team.bin `coach` resolves for 704/704 teams |
| Other pesdb `.bin` (Competition*, Tactics*, Country, Derby, …) | WESYS | No (passed through, container validated) | — |
| `EDIT00000000` (PES 2021) | PES 2020/2021 save encryption | Players, teams, rosters, coach name/country | decrypt → encrypt is byte-identical on the user's EDIT; coach section (0x958DA4, 1300 × 88 bytes, count u16 at 102) checked against Coach.bin |
| Sider `content/kit-server` | `map.txt`, `order.ini`, `<kit>/config.txt`, `.ftex/.dds` | 45 config keys + 7 texture slots | All 4 768 `config.txt` of the UML patch re-serialize byte-identical; 400/400 font FTEX parse |

Not supported: CPK archives (pesdb must be extracted / used from a livecpk folder), PES 2020 EDIT (rejected),
writing textures from decoded pixels (decoding is preview-only), team ID changes.

## 2. Investigation summary

- **PES Editor Rebuilt** (`vendor/Pes-Editor-Rebuilt-main`, v0.044 alpha, BSD-3): browser editor for
  `EDIT00000000` + Sider kit-server, not for pesdb BINs. Provided the EDIT crypto (libpesXcrypter port), the EDIT
  layout (4ccEditor port), kit-server handling (config.txt, order.ini, FTEX read/write, font glyph templates) and an
  independent partial Player.bin layout (`DB_ABIL` in `js/app.js`).
- **EJOGC PES 2020 Editor V0.12.8** (`vendor/Pes_2020_Editor_…`, .NET 4.6.2, config `Pes=2021`, `Mode=Bin`):
  reads the pesdb BINs. Source not available.
- **REA** (`rea-agents` 6.4.0, MCP + skill `reverse-engineer-anything`): identified the executable
  (`inspect-managed-artifact`: IL-only PE32, .NET 4.6.2, sha256 `51e967a1…`). `inspect-managed-members` stopped
  with *"Managed metadata exceeds the 67108864 byte representation budget"*; REA expects an external decompiler
  for method bodies. Decompilation was done with ILSpy (`ilspycmd` 8.2). Identifiers are obfuscated and strings
  encrypted (not circumvented); the numeric layout tables (`class _2056/_2057`, 149/148/12-entry `int[][]`) are
  readable and were extracted by `pes/tools/extract_layouts.cjs`.
- **WESYS container**: `FF 10 <flags> "WESYS" u32 storedSize u32 size`, flags `0x81` = zlib, `0x00` = stored.
  Confirmed on all 13 files; the Adler-32 trailer is verified on read (fflate does not).
- **Kits in the database**: EJOGC maps no Kit1–10 / colour fields for Team.bin in PES 2021 Bin mode; kits of the
  patch live in the Sider kit-server. EDIT team colours (6-bit RGB) are the only kit-related database fields.

## 3. Field evidence (`pes/formats/pes2021/binLayout.js`)

Generated by `pes/tools/gen_layout.cjs`; each field carries `evidence` and `confidence`:

- `verified` — exact agreement with real data (team CSV 704/704; player fields ≥85 % on 14 627 ID-matched players
  of an export from another season) or identical offsets in two independent sources (EJOGC + Rebuilt: names,
  height, age, nationality, all 20 outfield attributes).
- `structural` — editable, UI shows a warning: offset from EJOGC, labels by column order, 75–85 % agreement or
  value drift typical between seasons (weight, playing style, registered position, LMF/RMF/AMF ratings, japName).
- `unverified` / `partial` — **read-only**: the 5 GK attributes (EJOGC and Rebuilt label the same offsets
  differently; GK data could not decide), form, injury resistance, reputation, `nonPlayableLeague` (598/704).

Unlabelled EJOGC entries are not exposed; edits write only the bits of the edited field, so every other byte is
preserved (tested: one edit changes only bytes inside that field's span).

## 4. Architecture

```
pes/                      engine (no React, no Firebase)
  core/                   errors, WESYS container, field codec (bits/uint/bool/string)
  formats/pes2021/        binLayout (generated), binDatabase, editCrypto, editLayout, editDatabase
  kits/                   kitConfig, kitWorkspace, ftex, kitFonts, kitTextures, imageDecode (browser only)
  permissions.js          roles → capabilities, field-level authorize()
  operations.js           operation model, atomic batches with rollback, replay
  validator.js            new vs pre-existing issues
  teamReplacement.js      impact plan → operations
  exportService.js        validate → generate → verify → manifest → zip → verify zip
  session.js              file classification, source records, workspace build/replay
  storage/localStore.js   IndexedDB: original sources (by sha256), drafts, texture cache
services/pesWorkspaceService.js   Firestore: roles, workspaces, history, exports, validation
services/pesTextureStorage.js     Supabase Storage: texture files (content-addressed)
hooks/usePesWorkspace.js          React glue; hooks/usePesAccess.js sidebar gate
screens/PesWorkspaceScreen.jsx + components/pes/*   /pes route (lazy chunk)
```

**Working copy** = original sources (IndexedDB, never modified) + saved operations (Firestore, shared) + drafts
(IndexedDB, per browser). Every user rebuilds the same state; sources are matched by SHA-256 so nobody applies the
history to a different database. Binaries are never stored in Firestore or localStorage.

**Operations** (`OP_TYPES` in `pes/permissions.js`): `bin.team.set`, `bin.player.set`, `bin.assignment.set|add|remove`,
`edit.team.set`, `edit.player.set`, `edit.roster.number|player`, `edit.team.squad`, `edit.roster.remove`, `kit.set`,
`kit.texture.set`. Payloads are stored in Firestore as JSON text (`valueJson`/`beforeJson`/`afterJson`) because
Firestore rejects nested arrays. A failed batch is
rolled back; a saved operation can be discarded (state change, never deleted).

## 4b. Draft → PES (`pes/draftTransfer.js`, tab "Draft → PES")

Each draft team (marketplace user) replaces an existing game team. Input is the data `utils/pesExport.js` used for
the EJOGC CSVs (`teamName`, `country`, cart players, `dorsals`, `formation` + `lineup`, `setPieces`,
`tactics`), loaded by `services/draftTeamsService.js` (needs the app admin account: private profiles and carts).
The draft team → game team assignment is stored in the workspace (`draftMap`).

| Written | pesdb | EDIT |
|---|---|---|
| Name (all language slots / EDIT name + edit flag), abbreviation (pesExport rule: first 3 letters), country | ✓ | ✓ |
| Squad (≤ 40) with the user's shirt numbers (invalid or repeated → first free number) | PlayerAssignment.bin | roster slots |
| Starting XI in formation order, formation roles + positions (pesExport formula) in all 3 plans × 3 variants | — | ✓ |
| Strategy (app values; pressuring inverted, numbers in attack/defence +1), instructions/marking reset | — | ✓ |
| Captain and 9 set-piece takers (user picks; empty → best starter by Rebuilt's scores on Player.bin attributes) | — | ✓ |
| Transferred players removed from their previous club (national teams untouched); a starter is replaced by a substitute, captain/takers pass on; without substitutes the position stays empty and the club is reported | ✓ | ✓ |

The marketplace database is the same as the exported one (checked: all 27 072 `jugadores.json` ids exist in Player.bin
with identical name, height and age). A drafted id missing from the loaded base blocks the plan.
Planning simulates every operation on the working copy and rolls back; the user then applies, saves, validates and
exports as usual. Coach: optional per draft team (name + nationality). Every game team has its own coach (no coach is
shared in the database; Team.bin `coach` = EDIT `manager_id` for 704/704 teams), so the replaced team's coach record is
renamed in Coach.bin and in the EDIT coach section (edit flags raised); a shared coach is refused with a warning.
Not transferred: appearances, kits (kit-server is mapped by team id, so the replaced team keeps that slot's kits).

## 4c. Shared sources

When the Super Admin creates a workspace, each source is packed (`pes/storage/sourceArchive.js`) and uploaded to
Supabase Storage at `<workspaceId>/sources/<contentSha256>.pesdb|edit|kits`; other users download it automatically,
the content hash is verified and the copy is cached in IndexedDB. Upload is Super Admin only (bucket policy).

## 4d. Kits: 3D preview, fabric maps, new kits

Where things live in the UML patch: **values** (models, colours, name/number placement, which texture files a kit
uses) are in Sider's `content/kit-server/<league>/<team>/<kit>/config.txt`; the **texture files** themselves
(`u0126p1.ftex`, `dor_bla_num.ftex` …, about 7 000 BC7 FTEX) are in
`livecpk/UML_Kits/Asset/model/character/uniform/texture/#windx11`, and many kits also carry their own copies in the
kit folder (PSG `p1x1`, `uefa/*`). How Sider's kit-server module serves them (read from `modules/kserv.lua` v1.17,
loaded by `sider.ini` as `lua.module = "kserv.lua"`; there is no `kitserver.lua` in this install):
- `map.txt` maps team id → folder; `order.ini` / `gk_order.ini` list kit folders per `[section]` (non-default
  sections are tagged `CompKit`; with `hide_comp_kits_badges = 1` kserv.lua writes X=31,Y=0 to every badge key).
- `config.txt` is parsed as `key=value`, comment from the first `;`, BOM stripped, `tonumber` when numeric.
- The game itself derives `KitFile + "_srm"` and `NameFontFile + "_ex"`; kserv.lua adds both keys so it can remap them.
- For each texture key, kserv.lua checks `<kit-server>/<team>/<kit>/<name>.ftex` (**.ftex only**). If it exists the
  name is rewritten to `k<team>p<n>…` and served from that folder; otherwise the name is left alone and the game
  finds it through its CPKs / livecpk roots (`cpk.root` of `sider.ini`). `_nrm` is never remapped and the patch ships none.
- The editor ranges of kserv.lua's in-game config editor (`overlay_states`) are the validation reference
  (`pes/kits/kitConfigSchema.js`): the Kit Studio comments in config.txt are wrong for some keys
  (`ShortsNumberX ; 0 to 14` while kserv.lua accepts 0..31 and PSG p1 uses 16; Collar 1..135, ShortsModel 0..17,
  BackNumberSpacing 0..15). Values are never rewritten: the render keeps `{ raw, used }` per key.
- Sleeve badges are drawn by `SleeveBadge-ArmbandServer.lua` from `content/badge-server/<competition>/badge/badge.ftex`
  (`badge-left.ftex`, optional per-team subfolder), chosen by tournament id — competition assets, not kit assets. The native per-team files
`livecpk/UML_Kits/common/character0/model/character/uniform/team/<id>/<id>_DEF_1st_realUni.bin` (120 bytes: colours,
model bytes, texture names at 0x2C/0x38/0x48/0x58/0x68) hold the same data as config.txt and are replaced at runtime
by the kit-server, so the editor never writes them. Everything is keyed by team id: a draft team that replaces team
126 wears the kits of the folder mapped to 126 until that folder's kits are edited.

- **3D preview** (`components/pes/PesKit3DViewer.jsx`): garment models of the CometKIT previewer (via PES Editor
  Rebuilt, `public/kit3d/kitpack.bin`, downloaded on first use), parts chosen from config.txt (TightKit, Collar,
  ShortsModel, ShortSleevesModel, goalkeeper sleeves), WebGL fabric shader with stadium lights. Panels in tabs
  (Vista · Camiseta · Letras · Tela · Diagnóstico).
- **Texture resolution** (`pes/kits/kitAssetResolver.js`, pure; providers in `components/pes/kit3d/loadKitTextures.js`):
  kit-server files only (the kit's own folder), livecpk is not searched. Order: (1) textures imported in the workspace
  (`kit.texture.set`), (2) original kit-server files shared to the cloud — Firestore
  `pes_workspaces/{ws}/kit_textures/{teamId}` manifest (`files[encoded path] = { path, sha256, ext, size }`) + Supabase
  `<ws>/<sha256>.ftex`, hash-verified, cached in IndexedDB, (3) the game folder or the kit-server folder opened in the
  browser (read only). Lookups are cached per provider and path for the session; concurrent requests share one promise.
  "Compartir texturas" (Super Admin / Kit Manager of a league team, explicit click) uploads the .ftex found locally.
  Slots: kit, `_srm`, `_nrm` (optional, not used by the game), name, name `_ex`, back, chest, leg.
- **Decoding / lettering**: `pes/kits/textureDecode.js` (DXT1/3/5, BC7, RGBA8; verified on PSG's BC7 kit 2048²,
  name 2048×512 and back/leg 4096×512 sheets). Glyph cells of the name/number sheets match PSG's sheets; accented
  letters are in the `_ex` sheet (4096×2048) whose grid is not mapped yet, so they are drawn as the base letter.
  Placement (`pes/kits/kitDecalFormulas.js`) is the game's own math, read from this machine's PES2021.exe (a runtime
  image dumped by a read-only Sider module, analysed in Ghidra/ReVa) and its shaders (`data/dt00_x64.cpk` →
  `shaders/dx11/PesShaders_dx11.fsop`, entries XOR-obfuscated with one byte, DXBC disassembled with d3dcompiler_47):
  - kserv only calls `ctx.kits.set`; Sider's `kitinfo.cpp` packs each key into bits of the kit record (e.g.
    ShortsNumberX = bits 5–10 of 0x16). The game converts them in `FUN_141e58c80` (back), `FUN_141e58d90` (chest),
    `FUN_141e59150` (name), `FUN_141e59240` (NameStretch = 0.5 + n/6, 0 read as 3), `FUN_141e594a0` (shorts) with
    range tables at 0x142B464D0/0x142B46590. A step outside 0..max is rejected (position 0, size 0.01): not drawn.
  - Lettering is not painted into the kit texture. `FUN_1419e3c60` draws a 1600×256 "marking" texture (name in x
    0–0.64 on a 512×128 canvas, back number 0.64–0.88, chest number 0.88–1 × top half, sleeve badge below it);
    the shirt shader maps each region onto the kit UV with scale/offset from `FUN_141a86310` (`FUN_1419a4d20` name:
    centre v = NameY + [0, −0.002, −0.016, −0.019][NameShape], height NameSize/16, width NameSize·NameStretch/4;
    `FUN_1419a44f0` back number: width 1/(10−6s), height 1/(0.627451·(20−12s)), top at (0.27557 − 0.1·y)/0.627451;
    `FUN_1419a4bf0` chest: square ChestNumberSize/16 centred at (X, Y)). The shorts number is a 128×128 texture
    (`FUN_1419e3a30`, digits turned 90°) placed by the pants shader as a square ShortsNumberSize/16 centred at
    (ShortsNumberY, ShortsNumberX), turned 180° on the left leg (`FUN_1419a5000`).
  - Digits: `FUN_1419e2c10` (one digit in the middle half of its region; two digits 0.08·(spacing−1) apart, with
    fixed corrections for 1x, x1 and 11) and `FUN_1419e4a90` (digit cells). Names: `FUN_1419e1df0` with the glyph
    table at 0x142A96CE0 (A–Z and the accented letters of `NameFontFile_ex`); curved names add 6 px between letters
    and sit on circles of radius 672/336/292.
  Checked against in-game captures of FC Barcelona kit-server `Barcelona/p1` (1080p screenshots in the game folder,
  `PES2021 2026-10-15 *.png`, and `vendor/2026-10-14 14-53-26.mp4`): number ink height 0.151 vs 0.152 measured, name
  centre 0.3895 vs 0.387, name width and letter pitch match. Open: the light curve's end letters drop ~1.6× what the
  decoded formula gives; the viewer's shorts/shirt meshes are CometKIT's, not the game's FMDL models
  (`dt35_g4.cpk` → `Asset/model/character/uniform/{cloth,nocloth}/#Win/*.fmdl`), so the shape on the body can
  differ even with the same UV placement.
  Without the kit texture the config colours are used. Sleeve badges: positions are read and listed; the badge images (badge-server) are not drawn.
- **WebGL lifecycle** (`components/pes/kit3d/useKitGL.js`, `kitRenderer.js`): `KitGL.make` returns null instead of
  throwing; context loss/restoration is handled (re-upload on restore); `draw` disables its vertex attributes after
  each pass; collar thumbnails share one offscreen context (`sharedThumbRenderer`) instead of one per render, which
  was making the browser drop the main viewer's context.
- **Fabric maps** (`pes/kits/fabricMaps.js`): normal map = repeating weave (8 fabrics) + relief of the kit drawings
  from the texture brightness; SRM = shine/roughness of the fabric. Previewed live in 3D and saved as
  `<KitFile>_nrm.ftex` (DXT5 2048) / `<KitFile>_srm.ftex` (DXT1 1024) through the normal texture import.
- **New kits** (`kit.add`): copies a kit's config.txt into the next free `p<n>`/`g<n>` folder and appends it to
  the chosen `[section]` of order.ini / gk_order.ini, keeping every other line and the line endings. Allowed to the
  Super Admin and to Kit Managers for league teams. Not tested in game.

## 5. Authorization

| Role | Can |
|---|---|
| Super Admin (`pes_roles/<uid>.role = super_admin`, or the existing app admin) | everything: sources, teams, players, replacement, kits, export, roles |
| Admin del Draft | read only |
| Kit Manager (Lusitano, Talleres de Balvanera) | kit-server config keys, kit textures/fonts, EDIT team colours + UniColors, for league teams (`leagueTeamIds`, empty = all) |
| no role | no access; never sees the editor |

Enforced three times: `authorize()` before applying; `firestore.rules` on every persisted operation (type +
field + league + actor); Supabase Storage policies on texture files (`pes_role` claim). `tests/pes/rulesSync.test.js`
keeps the rule lists equal to the engine lists. Known pre-existing exception: the catch-all
`match /{document=**} { allow read, write: if isAdmin(); }` gives the hardcoded app admin unrestricted writes.

## 6. Setup

1. `firebase deploy --only firestore:rules`.
2. Supabase (textures): Authentication → Third-Party Auth → Firebase (project id); run
   `supabase/storage-policies.sql` with the placeholders replaced; set `VITE_SUPABASE_URL`,
   `VITE_SUPABASE_ANON_KEY`, `VITE_SUPABASE_TEXTURE_BUCKET` in `.env`.
3. Roles: assign in the app (Editor PES → Roles), then `GOOGLE_APPLICATION_CREDENTIALS=<service-account.json>
   npm run pes:claims -- --apply` (dry run without `--apply`). Users sign in again to receive the claims.
4. Super Admin: Editor PES → Fuentes → load the pesdb folder, `EDIT00000000`, the kit-server folder → create the
   workspace. Other users load the same files once (hash-checked).

## 7. Export

ZIP with only generated files: `common/etc/pesdb/<File>.bin`, `save/EDIT00000000`,
`content/kit-server/<team>/<kit>/config.txt` and texture files, plus `manifest.json` (timestamp, workspace, sources
with hashes, files with sha256, operation count, validation, warnings, per-file verification, compatibility
statement `gameTested: false`). Blocked while there are unsaved drafts or new validation errors. Install: pesdb into
a CPK or a Sider livecpk folder with the same path; EDIT replaces `Documents\KONAMI\eFootball PES 2021 SEASON
UPDATE\<id>\save\EDIT00000000` (back it up); kit files into the Sider `content/kit-server`.

## 9. Limitations / open items

- Nothing has been tested inside the game. Structural verification only.
- Team replacement keeps the team ID; appended PlayerAssignment rows copy the template row's bytes 13–15 (squad
  order / flags, semantics unknown) and changing the row count is format-valid but untested in game.
- GK attribute names, form, injury resistance, reputation stay read-only until confirmed (e.g. with a fresh
  EJOGC "Players" CSV export of `vendor/UML_Database`, which would also upgrade the structural fields).
- Generated/imported PNG textures are DXT5/DXT1 FTEX while the patch uses BC7 (both load in the game per Rebuilt).
  3D name/number placement is approximate (see 4d).
- Draft → PES does not transfer player appearances or kits; the coach is renamed, never created (adding Coach.bin /
  EDIT coach records is untested in game); the EDIT tactics layout comes from
  PES Editor Rebuilt ("verified in-game") and the user's EDIT, not from in-game tests of this tool.
- `jugadores.json` (marketplace) is generated by `scripts/main.py` from `jugadores_exportados.csv`; if it is ever
  regenerated from another database, load that same database in the editor (the plan reports unknown ids).
